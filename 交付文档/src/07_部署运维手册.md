# 第 1 章 系统结构

| 组成 | 内容 | 位置 |
|---|---|---|
| 数据库对象 | 存储过程、函数、视图和表，前缀 `MTC_CA_` | B1 公司库（HANA），每个公司一套 |
| 执行台服务 | Python 程序 `dev_server.py`，提供网页和查询接口 | 一台 Windows 服务器，开机自动运行 |
| 网页 | `index.html`、`css/`、`js/`，浏览器打开 | 由执行台服务提供，不需要外网 |
| B1 Service Layer | 验证登录密码，写日记账凭单、重估单、工时和期初价单据 | B1 服务器 |

执行台服务只做两类数据库操作：只读查询（在只读事务中执行，结束后回滚），以及调用登记过的成本过程（计算、检查、承接、场景维护等）。可以执行哪些查询和过程登记在 `actions.json` 中，网页不能提交任意语句。

## 1.1 数据库中的表

| 层 | 表名前缀 | 内容 |
|---|---|---|
| 运行日志 | `MTC_CA_RUN*` | 每次运行的状态、步骤、迭代过程，全部保留 |
| 配置 | `MTC_CA_C_*` | 参数、科目、费用池、校验登记；每次运行从 B1 同步 |
| 元数据 | `MTC_CA_M_*` | 表和字段说明，执行台“说明书”页使用 |
| 快照 | `MTC_CA_S_*` | 每次运行取的截至期末的输入数据 |
| 结果 | `MTC_CA_R_*` | 物料、订单、在产品、费用分摊、凭证底稿、校验结果 |
| 期初承接 | `MTC_CA_BOOT_*` | 上线时从旧系统承接的期初 |

同一账期、同一运行类型和场景，只保留最近一次成功运行的明细；失败、阻断、未收敛的运行保留日志和必要的排查数据。

## 1.2 入口过程

| 过程 | 用途 |
|---|---|
| `MTC_CA_P_RUN` | 正式或模拟计算 |
| `MTC_CA_P_PRECHECK` | 只做计算前检查 |
| `MTC_CA_P_BOOTSTRAP` | 期初承接（上线时一次） |
| `MTC_CA_P_LEGACY_LOAD` | 历史回填（把旧系统结果转成报表可查的历史数据） |
| `MTC_CA_RPT_*` | 成本报表，B1 查询管理器和执行台共用 |

这些过程一般都由执行台调用，不需要在数据库中直接执行。

# 第 2 章 安装前准备

| 项目 | 要求 |
|---|---|
| 服务器 | Windows Server，能访问 HANA 和 B1 Service Layer |
| Python | 3.8 以上，安装时勾选“所有用户”和“加入 PATH” |
| HANA 驱动 | HANA Client（ODBC）。Python 位数要与 HANA Client 一致；装了 hdbcli 时优先用 hdbcli |
| 数据库账号 | 能读当前公司库、执行 `MTC_CA_*` 过程，能读 `OUSR`、`CUFD` |
| 服务账号 | 一个专门运行服务的 Windows 本地账号，不要用个人账号 |
| B1 自定义对象 | 成本模块用到的用户定义表和字段（部署包执行时会列出缺少的） |

# 第 3 章 部署数据库对象

部署包 `部署包/` 可以单独复制到能连接 HANA 的电脑上执行，包内没有账号密码。

1. 双击 `部署.bat`（只装了 32 位 HANA Client 时用 `部署_32位.bat`），按提示选择连接、输入账号密码。
2. 程序显示连接的账号、租户和公司库，以及库中已有的成本对象数量；列出缺少的 B1 自定义表和字段。
3. **完整输入目标公司库名**确认，不一致时取消。
4. 程序按依赖顺序执行：已有的表、旧模块对象跳过不覆盖；新框架的表缺列时自动补列；视图、过程更新为本包的版本。
5. 结束时列出失败语句和无效对象，日志写到 `部署日志_<时间>.txt`。

部署后在执行台“期初承接”页执行期初承接（只在上线时做一次），需要时再执行历史回填。

> **注意**：B1 的 `SBO_SP_TransactionNotification` 不在部署包中。计算参数和费用池的保存校验是一段需要人工合入的代码，合入前先备份原过程。

# 第 4 章 安装执行台服务

1. 把执行台服务器包解压到服务器，例如 `D:\MTC执行台\`。
2. 复制 `console\server.example.json` 为 `console\server.json`，填写：
   - `schema`：默认公司库；`schemas`：可选的公司（多个公司时）。
   - `hana`：HANA 地址、端口、账号、密码（或 hdbuserstore 键）。
   - `sl.url`：Service Layer 地址；`sl.company`：公司数据库名。
   - `allowNets`：允许访问的网段。
3. 密码加密（建议）：在服务器上执行 `python console\dev_server.py --server --set-password`，输入两次密码，`server.json` 中写成 `"password": "dpapi:..."`。加密后只有这台服务器能解开。
4. 收紧 `server.json` 的文件权限：只留管理员和服务账号。
5. 在 B1 中添加权限字段：“工具 → 定制工具 → 用户定义字段 - 管理 → 设置 → 常规 → 用户”，字段名 `MTC_CARole`，描述“成本执行台权限”，类型“字母数字”，长度 1，有效值 R 查看、O 操作、A 管理，不设默认值。然后给每个用户设置权限（见《B1 配置维护手册》第 2 章）。
6. 试运行：双击 `run_server.bat`，看日志中出现“访问地址”，用另一台电脑的浏览器打开并登录。确认后**关掉这个窗口**。
7. 正式运行：右键 `install_service.bat` → 以管理员身份运行，输入服务账号和允许的网段。脚本注册开机任务“MTC Cost Console”并开放防火墙端口。
8. 需要 HTTPS 时，把证书和私钥（PEM）放在 `console\`，`server.json` 中写 `"tls": {"cert": "server.crt", "key": "server.key"}`，然后重启服务。账号密码要经过网络传输，建议启用。

正式运行后服务在后台运行，开机自动启动，不需要有人登录服务器；程序意外退出会自动重启。

# 第 5 章 日常运维

## 5.1 重启

右键 `restart_service.bat` → 以管理员身份运行。脚本停止任务、结束残留进程、重新启动，并显示日志最后几行。

> **注意**：重启会断开所有人的登录。**有人正在计算时不要重启**，计算会中断。顶栏有“运行中”提示时先等计算结束。

## 5.2 升级

| 改了什么 | 覆盖哪些文件 | 要不要重启 |
|---|---|---|
| 页面、使用手册、查询白名单 | `console\index.html`、`login.html`、`actions.json`、`console\css\`、`console\js\`、`console\img\`、`console\srcsql\` | 不用，用户刷新浏览器即可 |
| 服务程序 | `console\dev_server.py`、`hana_odbc.py`、`dpapi.py` | 要 |
| 配置、证书 | `console\server.json`、证书文件 | 要 |
| 数据库对象 | 重新执行部署包 | 不用；执行时不要有人在计算 |

覆盖时不要删除 `console\server.json`、`console\logs\`、`console\audit\`。

## 5.3 日志

| 文件 | 内容 |
|---|---|
| `console\logs\server.log` | 服务启动、退出、报错、每次登录的验证过程 |
| `console\logs\access-年月.jsonl` | 登录、登录失败、无权限、发起计算、场景维护、计算结束 |
| `console\audit\` | AI 助手的出网审计（目前未接入大模型） |

日志只保存在服务器上，不要外发。

## 5.4 查看运行状态

PowerShell 中执行 `Get-ScheduledTask -TaskName 'MTC Cost Console'`，State 为 Running 表示正在运行；也可以看 `server.log` 最后几行。

## 5.5 卸载

```
Unregister-ScheduledTask -TaskName 'MTC Cost Console'
Remove-NetFirewallRule -DisplayName 'MTC Cost Console'
```

# 第 6 章 故障排查

| 现象 | 排查 |
|---|---|
| 浏览器打不开 | 服务是否在运行；防火墙端口；访问电脑是否在 `allowNets` 网段内 |
| 登录一直“正在验证…” | 看 `server.log`：停在“正在经 Service Layer 验证密码”是 Service Layer 连不上或很慢，检查 `sl.url` 和 Service Layer 服务；停在“正在读权限”是连不上 HANA |
| 登录提示没有权限 | 用户主数据的权限字段为空 |
| 启动报 -10709 | HANA 地址或端口不对 |
| 启动报 10 或 414 | HANA 账号或密码不对 |
| 启动报 -10104 Invalid value for KEY | hdbuserstore 键不是用服务账号创建的 |
| 页面提示账套不可用 | 该公司库没有部署成本对象，或数据库账号没有权限 |
| 计算失败 | 在“步骤”页复制报错；出错步骤和报错原文是排查的起点 |
| 迭代未收敛 | “步骤”页的迭代过程列出每轮单价变化；系统保留最后一轮的中间结果和单价变化最大的物料，供排查 |
| 生成凭单失败 | 看“生成凭单”页每个凭证代码的报错；常见原因是科目不能记账、Service Layer 会话过期 |

# 第 7 章 安全

- 登录密码交给 B1 Service Layer 验证，执行台不保存密码；验证后立即登出。连续失败 5 次暂停 5 分钟。
- 空闲超过设定时间（默认 8 小时）要重新登录；服务重启后所有人重新登录。
- 操作人一律取登录账号，写进运行记录，页面上不能修改。
- 正式计算、期初承接、历史回填要完整输入公司库名确认；生成凭单还要输入本人 B1 密码。
- 网页不引用任何外网资源，内网电脑不能上网也可以使用。
- 使用手册中的截图经过脱敏处理，不含真实业务数据。
