# B1 自定义表：费用池与计算参数

用户 2026-10-14 决定：费用归集 / 分摊的配置在 SAP B1 里维护，成本执行台不做编辑页。新框架每次计算或“只做检查”时，先由 `MTC_CA_P05_CFG_SYNC`（步骤 P05）把这些表同步到 `MTC_CA_C_POOL*` / `C_ACCT` / `C_PARAM`，再取快照和计算。

- 表没建或没有数据：沿用 `MTC_CA_C_*` 里的种子值，步骤 P05 显示“沿用”。
- 有数据：费用池三张表整组覆盖；计算参数只覆盖 B1 里出现的参数代码（参数目录 `MTC_CA_C_PARAM_DEF` 登记的 47 个）。
- 配置有错（重复、账期格式、账期段重叠、默认池或关单差异池不是正好 1 个、不认识的参数代码、取值类型不对等）：这一组不覆盖，P05 记 FAIL，计算前检查 PRE-18 阻断，明细里写明原因。
- **保存时校验**（用户 2026-10-28）：执行 `新框架/sql/20_b1cfg_check.sql` 并把 `20_b1cfg_tn_snippet.sql` 合进 B1 的 `SBO_SP_TransactionNotification` 后，在 B1 保存计算参数或费用池时就会提示错误（“[成本配置] …”），不用等到计算。校验口径是视图 `MTC_CA_V_B1CFG_ISSUES`，P05 和执行台“B1 维护数据 → 检查 B1 配置”用的是同一个。
- B1 里删掉的参数**不会**回到种子值，沿用上一次从 B1 同步的值；要恢复默认值，在 B1 里填回默认值。
- PRE-18 还会检查：成本中心在 OPRC 中存在、本期只有一条；物料组 / 车间类别在 OITB 中存在；同一产品只属于一个池。
- 修改历史：注册 UDO 时勾选“日志”，B1 自动保留每次修改（`@AMTC_CA_POOL` 等），可在 B1 里看“更改日志”。

在 B1：工具 → 定制工具 → 用户定义的表 – 设置 建表，用户定义字段 – 管理 加字段，对象注册向导 注册 UDO。表名、字段名请照抄（代码按名字读取）。

## 1. 费用池 `MTC_CA_POOL`（主数据 UDO，代码 `MTC_CA_POOL`）

## 2. 计算参数 `MTC_CA_PARAM`（主数据 UDO，代码 `MTC_CA_PARAM`，平铺表格）

用户 2026-10-28 决定：参数改成**一张平铺表格**，打开就能看到全部参数，像 Excel 一样直接改。取代原来的 `@MTC_CA_EXPSET` + `@MTC_CA_EXPSET1`（一个参数一张卡片，见本节末“从旧表迁移”）。

| 表 | 名称 | 类型 |
|---|---|---|
| `MTC_CA_PARAM` | 成本计算参数 | 主数据 |

UDO：类型“主数据”，**没有子表**；默认表单的界面样式选“**矩阵**”（Matrix，一行一条记录；如果你们的 B1 版本没有这个选项，照常注册，平铺的总览看执行台）；勾选“查找”“默认表单”“日志”；不要勾选“可取消”。默认表单的列按下表顺序选。

| 字段 | 说明 | 类型 | 长度 | 填法 |
|---|---|---|---|---|
| Code（系统） | 参数代码 | — | ≤ 50 | 见下面各表的 Code。同一参数第二段起写 `参数代码@起始账期`，如 `TAIL_MAX@2026-11` |
| Name（系统） | 中文名 | — | — | 导入时写好，只是提示 |
| `Category` | 分类 | 字母数字 | 20 | 导入时写好：费用归集 / 计算控制 / 尾差与校验 / 凭证与对账 / 业务口径 |
| `FromFc` | 起始账期 | 字母数字 | 7 | `2026-11` 格式；空 = 不限 |
| `ToFc` | 截止账期 | 字母数字 | 7 | 空 = 不限 |
| `Value` | 取值 | 字母数字 | 200 | 见下面各表 |
| `DataType` | 类型 | 字母数字 | 10 | 导入时写好：数字 / 整数 / 文字 / 列表 / 账期 / 日期，只是提示 |
| `Hint` | 填法 | 字母数字 | 254 | 导入时写好：可选值、单位、例子 |
| `Locked` | 锁定 | 字母数字 | 1 | 有效值 `Y` 锁定 / `N` 不锁定，默认 `N`（2026-10-29 加，可选）。见下面“锁定” |

一行 = 一个参数在一段账期内的取值。每次开始计算、只做计算前检查、期初承接时，程序先把这张表抽取到新框架的 `MTC_CA_C_PARAM`（P05），再用抽取后的值计算（用户 2026-10-29）。B1 里出现的参数以 B1 为准（该参数各账期的值全部按 B1 替换），没出现的沿用新框架现有值。`CLOSE_DIF_POOL`（关单差异进哪个池）不在这里，在费用池表头的“关单差异池”维护。参数清单和类型登记在新框架的参数目录 `MTC_CA_C_PARAM_DEF`（`04_seed.sql`；`GOODS_TAIL_MAX` 在 `15_p70_tables.sql`，`RPT_GRP_CLASS` 在 `21_reports.sql`），以后加参数先在那里登记，再用导入脚本写进 B1。

填法：“列表”直接用逗号分隔（`A,B,C`，中文逗号也可以），不用在前后加逗号；单独的一项“空”表示空代码（只有 `EXP_JDT_TRANSCODES` 用到）；“数字 / 整数”必须是数字；“账期”是 `YYYY-MM`，“日期”是 `YYYY-MM-DD`；`RECON_BLOCK_ON` 只能是 `CUR` / `END`。运行记录（`MTC_CA_RUN.Params`）里记的是同步后本期实际用的值。

**某个参数要从某期起改值**：把原来那行的截止账期填成上一期，再加一行：Code = `参数代码@新账期`，起始账期 = 新账期，填新值。已经算过的账期重跑时仍取旧值。同一参数的账期段不能重叠（保存时校验会拦住）。

**这些参数不建议业务人员改**：计算控制里的 `CONV_PRICE`、`CONV_AMT`、`MAX_ITER`、`LEVEL_GUARD`（算法控制），`START_FC`、`BOOTSTRAP_FC`（上线后改会打乱期初承接），以及 `COST_TRANSCODES`（必须和代码实际生成的凭证代码一致）。建议把它们的“锁定”填 `Y`。

**锁定**（用户 2026-10-29）：“锁定” = `Y` 的行，B1 保存时不允许改起始账期、截止账期和取值，也不允许删除（提示“[成本配置] …已锁定”）。确需修改，先把这行的锁定改成 `N` 保存，再改值；谁能改锁定由 SAP 的 UDO 权限控制，程序不另做限制。判断“改没改”用的是新框架里的快照表 `MTC_CA_C_PARAM_B1`（B1 每次保存成功、程序每次同步时刷新），所以：
- 要合入 TN 校验片段（`20_b1cfg_tn_snippet.sql`）才生效；要拦删除，TN 片段要用 2026-10-29 的新版（多了 `D`）。
- 加好字段后重新部署（或执行一次 `20_b1cfg_check.sql`），末尾会把现有参数记一次快照，锁定从这时起生效。
- 没加 `Locked` 字段时一律当作不锁定，其他功能不受影响。
- 执行台“B1 维护数据 → 计算参数”有“锁定”列。

### 初始数据和从旧表迁移

1. 在 B1 建表 `MTC_CA_PARAM`、加上面 7 个字段（`Locked` 可以以后再加）、注册 UDO（矩阵样式）。
2. 用部署包部署（或执行 `新框架/sql/patch_20261028_param_ui.sql`、`07_snapshot_procs.sql`、`20_b1cfg_check.sql`）。部署包会在 B1 的表和字段（含 `OPRC.U_CalType`）都建好时自动装校验视图和 TN 校验过程，缺了会提示跳过；**没有校验视图时 P05 不同步 `@MTC_CA_PARAM`**，所以 B1 补齐后要重新部署一次。
3. `python3 新框架/tools/sl_import_costcfg.py --param --dry-run` 看要写入哪些行，去掉 `--dry-run` 正式写入：全部 47 个参数都会建好，取值优先取旧 `@MTC_CA_EXPSET1` 里的，没有的取新框架现在的值；中文名、分类、类型、填法一起写好。已有的 Code 跳过；以后参数目录的说明改了，用 `--param --update-meta` 只刷新说明，不动取值。
4. 把 `20_b1cfg_tn_snippet.sql` 那一段合进 B1 的 `SBO_SP_TransactionNotification`（先备份原过程）。部署不会自动改 TN，只能人工合入。合入后 TN 依赖 `MTC_CA_P_B1CFG_TN` 和视图 `MTC_CA_V_B1CFG_ISSUES`：执行 `99_drop_all.sql` 或重建库后没执行 `20_b1cfg_check.sql` 时，B1 里保存计算参数和费用池会报错，重新执行 `20_b1cfg_check.sql` 或先注释掉 TN 里那一段即可。
5. 执行台点“只做计算前检查”：P05 显示“计算参数：已从 B1 @MTC_CA_PARAM 同步 N 行”，PRE-18 通过；“B1 维护数据 → 计算参数”里各参数状态为“一致”。
6. 确认无误后，在 B1 删除旧 UDO `MTC_CA_EXPSET` 和表 `MTC_CA_EXPSET` / `MTC_CA_EXPSET1`。`@MTC_CA_PARAM` 有数据时 P05 不再读旧表；它没有数据时才回退读旧表。

## 3. 执行台权限字段 `OUSR.U_MTC_CARole`（用户定义字段）

只有执行台**服务器模式**（多人用 B1 账号登录）需要；本机模式不用。用户 2026-10-18 要求**在 B1 前台手工加，不用 SQL 或脚本**。

1. 其他用户先退出 B1 客户端。
2. 工具 → 定制工具 → 用户定义字段 - 管理 → 展开“设置 → 常规 → 用户” → 添加：

| 字段名 | 描述 | 类型 | 长度 | 有效值 | 默认值 |
|---|---|---|---|---|---|
| `MTC_CARole`（系统自动加前缀成 `U_MTC_CARole`） | 成本执行台权限 | 字母数字 | 1 | 勾选“设置有效值”：`R` 查看、`O` 操作（只做检查、模拟、场景）、`A` 管理（正式计算、期初承接、生成凭单） | 不设 |

3. 管理 → 设置 → 常规 → 用户，打开每个用户，在用户定义字段栏（菜单“视图 → 用户定义字段”）选权限；空 = 不能登录执行台。改完下次登录生效。字段名如果要换，同时改 `server.json` 的 `roleField`。详见 `tools/README.md`“服务器部署”。
