# 新框架对旧框架对象的依赖

新框架（`MTC_CA_*`）读了哪些旧框架对象，以及旧对象变了会影响什么。**只读代码整理，未在库上验证。**

- 首次整理：2026-11-02（扫描 `新框架/sql/*.sql`、`tools/console/`、`新框架/tools/`、`新框架/reports/`，不含 `_backup/`）
- 维护规则：新框架代码新增、删除或改动对旧对象（`MTC_COST_*`、`MTC_VIEW_*`、`U_COILV`、旧模块建的 `@MTC_*` / `@U_*` 表）的引用时，同步更新本文件，并在末尾“变更记录”加一行。

重新扫描用的命令：

```sh
cd 新框架/sql
grep -nE 'MTC_COST_[0-9]|MTC_COST_PROC|MTC_VIEW_|MTC_CO_001|U_COILV|MTC_RPT_|MTC_PRT_|@MTC_COST_|@MTC_OMRV|@MTC_PTPRICE|@MTC_SALORDTYPE|@MTC_OWOR|@MTC_WOR1|@U_CIOTRN|@U_CITRN1' *.sql | grep -v '^99_drop'
```

## 总结论

- 新框架**不写、不改、不删**任何旧表 / 旧视图（没有 INSERT / UPDATE / DELETE / DROP），也**不调用**任何旧过程，所以旧流程（0000 等）照常运行，不受新框架影响。
- 反过来，新框架会**读**一部分旧对象，这些旧对象的定义或数据变了，新框架的结果可能跟着变。

## 一、旧框架计算结果表（`MTC_COST_*`）

| 新框架用在哪 | 读的旧表 | 用途 | 旧表变了的影响 |
|---|---|---|---|
| 期初承接 `MTC_CA_P_BOOTSTRAP`（`sql/09_bootstrap.sql`） | `MTC_COST_0301_INVNT`、`0321_OWOR`、`0321_OWOR1`、`0321_OWOR_SUM`、`0322_OWOR_ZCP`、`0322_OWOR_ZCP1` | 起始账期（`BOOTSTRAP_FC`）的物料期末、订单在产品、订单 × 材料在产品、料工费比例 | 只在承接时读一次，结果存进 `MTC_CA_BOOT_*`；之后旧表再变不影响，除非重新承接 |
| 新旧比对 P65 `MTC_CA_P65_COMPARE`（`sql/14_p50_p60_p65.sql`） | `0301_INVNT`、`0321_OWOR_SUM`、`0322_OWOR_ZCP` | 物料期末 / 单价、订单成本、在产品比对 | 只影响比对结果；旧框架该账期没跑就跳过 |
| 无原单销售退货价 SRT（`sql/12_p30_init.sql`，`prevOld`） | `0302_INVNTDETAIL1`（ObjType 15） | 原交货在承接前账期时取旧成本（全部记材料） | 限定 `FcCode <= BOOTSTRAP_FC`；重跑旧框架历史账期会改变这部分退货价 |
| 交货单位成本 P71 `MTC_CA_R_DNCOST`（`sql/16_p70_jdt.sql`，`old`） | `0302_INVNTDETAIL1`（ObjType 15 / 16） | 第三顺位兜底：本期新框架 → 以前账期新框架 → 旧框架 | 限定 `FcCode <= BOOTSTRAP_FC`（2026-11-02）；重跑旧框架历史账期会改变兜底价 |
| PRE-23 期初价建议（`sql/12_p30_init.sql`，`seen` / `hist`） | `0301_INVNT` | 判断以前是否出现过、给建议价（优先级排在新框架结果之后） | 只影响建议价和清单 |
| 料工费比例 `MTC_CA_P_LEGACY_RATIO`（`sql/09_bootstrap.sql`，承接和回填共用，2026-11-02 从承接抽出） | `0321_OWOR_SUM`、`0321_OWOR1` | 截至某账期最近一个有完工的账期的完工成本比例，材料按领料逐级展开 | 同承接 / 回填 |
| 历史回填 `MTC_CA_P_LEGACY_LOAD`（`sql/22_legacy_load.sql`，报表合并，2026-11-02） | `0301_INVNT`、`0302_INVNTDETAIL1`、`0321_OWOR`、`0321_OWOR1`、`0321_OWOR1_REG`、`0321_OWOR_SUM`、`0322_OWOR_ZCP1`、`0801_TOOJDT`、`0802_OJDTBASEDETAIL`、`U_COILV` | 承接账期及以前每期一次历史运行（RunType H），成本报表取它；核对 `22_legacy_verify.sql` 还读 `0322_OWOR_ZCP` | 回填时读一次，存进 `MTC_CA_S_*` / `R_*`；之后旧表再变不影响，除非重新回填（重新回填某期后，以后各期也要重新回填） |
| 历史委外差异清单 `MTC_CA_P_WW_HIST_LOAD`（`sql/19_ww_hist.sql`，2026-11-04） | `0322_OWOR_ZCP`（另读 B1 `OWOR`、`@MTC_OWOR`） | 载入承接前已关闭、在产品不为 0 的委外订单 | 只在点“刷新清单”时读；已载入的行存在 `MTC_CA_WW_HIST`，停用旧框架后清单不再更新 |

## 三、旧模块建的 B1 自定义表（业务维护数据，新旧共用）

| 表 | 新框架用途 |
|---|---|
| `@MTC_COST_IOTYPE` | 交易类型 Code / 方向（P20_LINE、P30、报表 R 系列） |
| `@U_CIOTRN`、`@U_CITRN1` | 59 / 60 的业务类型 `U_TrsName` |
| `@MTC_COST_QCPRICE(1)` | 期初维护价快照 `MTC_CA_S_QCPRICE`；执行台“生成 B1 单据”会经 Service Layer 写它（用户确认后） |
| `@MTC_COST_TIME(1)` | 单位工时快照 `MTC_CA_S_HOURS`；执行台“生成 B1 单据”同上 |
| `@MTC_OMRV(1)` | MRV1 重估 → I11；ProWW → 订单加工费；WW 单不再读（改由 P20_AP 计算） |
| `@MTC_PTPRICE(1)` | P70 样品价 |
| `@MTC_SALORDTYPE` | 销售订单类型、国内 / 国外客户 |
| `@MTC_OWOR`、`@MTC_WOR1` | 返工单头 / 行 |

这些表的配置或数据一改，新旧两边同时变。

## 四、不依赖的旧对象

- `MTC_CO_001GetItemLevel`：P20_ITEM 替代；种子数据 `MTC_CA_C_LEVEL_OVR` 抄了旧过程写死的 4 个物料。`U_COILV` 新框架计算不读，只有历史回填读它取历史期层级。
- `0201_DOCDETAL`、`0303_INVNTLIST`、`0321_OWOR2` 等：新框架不读（只有 `export_masked.py --set old` 只读导出）。`0801_TOOJDT`、`0802_OJDTBASEDETAIL` 只有历史回填读。
- 所有 `MTC_COST_PROC_*`、`MTC_RPT_*`、`MTC_PRT_*` 过程：不调用。

## 五、会影响新框架的情况

1. **改 `MTC_VIEW_Document`**：P20_LINE 结果会变，要 RECOMPILE 依赖它的新过程。
2. **改 `@MTC_COST_IOTYPE` / `@U_CIOTRN` 配置**：新旧同时变。
3. **重跑旧框架的历史账期**（旧过程先 DELETE 再 INSERT）：会改变 P71 兜底价、SRT 退货价、PRE-23 建议价、P65 比对；已承接的 `MTC_CA_BOOT_*` 不变，除非重新承接。
4. **停用旧框架**：可以不再跑 0000，但第一节的旧表和 `MTC_VIEW_Document` 必须保留；HANA 过程是静态引用，删表后承接、回填、P65、P30、P71 过程都会失效。
   历史回填做完、`22_legacy_verify.sql` 核对通过后，成本报表看历史期不再读旧表（数据已在 `MTC_CA_*` 里）；但承接、回填过程本身仍引用旧表，删旧表前要先删这些过程（或接受它们失效）。
