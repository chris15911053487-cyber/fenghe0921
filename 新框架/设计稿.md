## 1. 目标与原则

| 原则 | 落实方式 |
|---|---|
| 一次运行得出结果，与运行次数无关 | 关单差异、期初维护价、返工、形态转换统一放进一个迭代循环，收敛后才写结果（S1、S2、S3、S5.5） |
| 层级不写死 | 逐级计算是一个循环，层数取自本期物料层级表；层级 -1 是阻断错误（S0） |
| 截至期末 | 快照只取过账日期 ≤ 期末的单据；订单状态、关单日期也按期末判断，不用当前 LineStatus / OpenQty |
| 每个数字可追溯 | 每行结果带“价格来源”和“规则编号”；另有成本构成表，单价和订单成本可逐层追到原单据行（R4） |
| 结果全部落静态表 | 输入快照、过程、结果三层都落表；报表和凭证只读这些表（R1） |
| 新表另建，旧流程不动 | 新对象统一前缀 `MTC_CA_`，旧 `MTC_COST_*` 一律不改；并行期逐表比对（R2） |
| 规则即数据 | 科目、参数、层级覆盖、校验、AI 工具都登记在配置表，带编号和中文说明 |
| 数据不出本地 | AI 只拿到元数据和执行状态（A 档）；解释、分析由本地存储过程生成（R5、R6） |

### 1.1 不变的部分（沿用）

- B1 中用户维护的单据和配置：`@MTC_COST_IOTYPE`、`@U_CIOTRN`、`@MTC_COST_TIME(1)` 工时、`@MTC_COST_QCPRICE(1)` 期初维护价、`@MTC_SALORDTYPE`、`OTRC`，维护界面不变。
- 视图 `MTC_VIEW_Document`（单据行 → TransCode、订单、配对键）、表函数 `MTC_COST_FC_DOCDETAIL`：快照层直接调用，不复制逻辑。
- 业务规则：交易类型方向、采购入库金额取数（U_InitPrice 优先）、发票差异、费用来源凭证类型、分摊基础（单位工时 × 本期入库数）、凭证分段规则。

## 2. 命名与通用约定

### 2.1 对象前缀

| 前缀 | 用途 |
|---|---|
| `MTC_CA_RUN*` | 运行日志、步骤日志、指标快照、迭代日志 |
| `MTC_CA_C_*` | 配置与规则（Config） |
| `MTC_CA_M_*` | 元数据：数据字典（Meta） |
| `MTC_CA_S_*` | 输入快照（Snapshot） |
| `MTC_CA_R_*` | 计算结果（Result） |
| `MTC_CA_P_*` | 存储过程（Procedure） |
| `MTC_CA_V_*` | 语义视图（给报表、执行台、AI 工具用） |

### 2.2 运行键与留存（R1）

- 每次运行生成 `RunId`（序列 `MTC_CA_SEQ_RUN`）。
- 运行键 = `FcCode + RunType + Scenario`。`RunType`：`F` 正式、`S` 模拟；正式运行的 `Scenario` 为空串。
- 所有 `S_` / `R_` 明细表都带 `FcCode, RunType, Scenario, RunId`。
- **只保留最后一次成功运行的明细**：新运行先按自己的 `RunId` 写入；成功后删除同一运行键下旧 `RunId` 的行；失败则删除本次 `RunId` 的行。所以运行中途失败不会破坏上一次的结果。
- 运行日志 `MTC_CA_RUN`、步骤日志、迭代日志、指标快照 `MTC_CA_RUN_KPI` **每次运行都保留**。

### 2.3 字段约定

- 数量、金额带符号：入库为正、出库为负（与旧 0302 一致）。O06 销售退货方向为入。
- 成本要素四列贯穿全流程：`MatAmt` 材料、`MfgAmt` 制造费用、`LabAmt` 人工、`SubAmt` 委外加工费；`Amount = 四项之和`。物料单价也分四项，成本还原不用另算。
- 订单键一律 `OrderType + OrderEntry`（`202` / `MTC_OWOR` + DocEntry），任何按订单的关联都必须两列同时带（#28）。
- 单据行键 `ObjType + DocEntry + LineNum`，可直接回查 B1。
- 计算过程用 DECIMAL(19,6)；金额最后按 2 位小数取整，尾差挤进同组金额最大的一行，并记规则编号（S16）。
- 每张表、每个字段在库中写 `COMMENT`，同时登记到 `MTC_CA_M_TABLE / MTC_CA_M_COLUMN`（含粒度“一行代表什么”、单位、正负号）。

## 4. 计算流程

入口：`MTC_CA_P_RUN(FcCode, RunType, Scenario, UserCode, Initiator)`。

```
P00 准备      账期锁定检查；建运行头；读参数
P20 快照      写 S_ 各表（截至期末）
P10 计算前检查  在快照上检查，只读；有阻断项就停止，保留检查结果和本次快照（第 6 节；2026-11-04 起同运行键只留最近一次）
P30 固定价格   采购入库、发票差异、重估、I90、取消单配对、不计价标记
P40 迭代 ──┐  第 k 轮：
           │  P41 预定价交易：用上一轮的物料加权价（第 1 轮用维护价，没有就用上期期末单价）
           │  P42 费用池 = 凭证费用 + 公摊材料（按 P41 价格）+ 关单差异（上一轮）+ 重估，按 4.4 归入各池
           │  P43 各池直接分摊到订单（4.4）
           │  P44 委外加工费按订单归集
           │  P45 逐级：L = 0 … 本期最高层
           │        a 本层订单的领料按子件当前单价计价
           │        b 订单 × 材料结转（S5 公式）
           │        c 订单完工成本 → 本层入库行
           │        d 本层物料加权单价（含 I05、退货、其他入库）
           │        e 本层物料出库按新单价计价
           │  P46 关单差异 = 本期关单订单的剩余在产品
           │  P47 收敛判断；写迭代日志；未收敛且未到上限 → 下一轮
           └─
P50 落表      R_ 各表、成本构成
P60 校验      执行登记的 POST 校验；写指标快照
P70 凭证      （第 3 期）
P80 收尾      删除同运行键的旧明细；运行状态 = 成功
```

### 4.1 各类交易的定价规则

| 交易 | 定价 | 场景 |
|---|---|---|

| I11 库存重估 | `@MTC_OMRV` WW/MRV1 行金额；U_CalType = InvntCost 的不计价 | S13 |
| I03/I07/I09/I08/I90 生产、返工、委外入库 | 订单本期完工成本 ÷ 本期入库数 × 行数量；尾差挤最大行 | S5 |
| O03/O07/O08/O09/O90 订单领料 | 子件本期加权单价（四项） | S5 |
| O03/O07 中业务类型 304 生产退料 | 该订单该材料截至本期的平均领料单价；取不到用物料加权价 | S8 |
| O01 销售出库 | 本期加权单价 | S10 |
| O06 销售退货（有原单；原单取 RDN1 标准来源，不是交货时取行上 U_BaseType / U_BaseEntry / U_BaseLine【用户确认 2026-10-13】） | 原交货行成本（原交货在本期取本期结果，在以前账期取该期 R_LINE；2026-08 及以前取旧 0302） | S10 |
| O06 销售退货（无原单） | 期初维护价，作为最终价格；没有维护价按本期加权价（SRT-03）。允许发生，PRE-04 只警告【用户确认 2026-10-13】 | S10 |
| 应收贷项凭证（14）直接退货入库 | 用户确认没有这种场景（Q6），不计价；万一出现，TransCode 识别不了，被计算前检查拦截 | S10 |
| O05 形态转换出库 | B 的本期加权单价（迭代中更新） | S3 |
| I05 形态转换入库 | = 配对 O05 的金额（一对一、同月，计算前检查保证） | S3 |
| I04/O04/I10/O10 其他出入库、盘点、试打领用（O04） | 物料本期加权单价（迭代中更新）；记 5101 的金额进入费用池 | S1、S7、S9 |
| 取消单 | 原单成本反向 | S10 |
| 报废 305/311/207（数量 ≠ 0） | 不计价（沿用旧规则，原因写入行上） | S14 |
| 本期算不出价格的物料（无期初、无任何有价入库） | 期初维护价，标注“兜底价”；仍没有则报警告、单价为 0 | S1 |

### 4.2 订单结转与在产品（S5，用户已确认）

按“订单 × 材料”：

```
累计领料金额 A = 截至上期累计 + 本期领料（四项分别计）
结转比例     r = min(累计入库数 ÷ 订单计划数, 1)
本期结转     = A × r − 以前各期已结转
期末在产品   = A − 累计结转
```

- 订单完工成本 = Σ 材料本期结转 + 本期分摊的制造、人工 + 本期结转的委外加工费。
- 人工、制造只分摊给本期有入库的订单，不进在产品。
- 委外加工费【用户确认 Q3】：订单本期有入库时，截至本期累计归集、尚未结转的加工费**全部**结转到本期入库（加工费按收货发生，不按比例）；本期没有入库时留在订单上作为加工费在产品，下次入库时结转；订单关单时剩余加工费转关单差异。用户说明理论上加工费与入库同期，所以出现留存时 POST 校验给出提示。（全部结转、不按比例：【用户确认 2026-10-11】）
- 全部入库后再补的领料：比例已是 1，但本期没有入库可承接时留在在产品，关单时转关单差异。
- 订单本期关单（截至期末状态为关闭、关单日期在本期，【用户确认 Q4】）：剩余在产品 = 关单差异，进入下一轮迭代的费用池；订单在产品清零。
- 返工单（WorType 30）同一公式。领用的 A 与产出的 A 同层：领料按上一轮 A 的单价，迭代收敛后一致（S2）。

### 4.3 迭代与收敛

- 每轮从快照重新计算，只把“上一轮的物料单价、关单差异”作为输入。结果只取决于快照和参数，与运行次数无关。
- 收敛：所有物料四项单价变化 ≤ 0.000001，且费用池、关单差异变化 ≤ 0.01 元。
- 达到最大轮数仍未收敛：运行状态 = 未收敛，不写结果明细（保留上一次结果），迭代日志列出变化最大的物料，供排查。
- 预期几轮内收敛：每轮回流的只是费用中的一小部分；返工回流比例 = 返工领用量 ÷ 该物料可用总量。

**重要发现【读代码】**：PUR3 不只生成凭证。它写的 WW 重估单会被成本计算当作产品的 I11 入库读进去（旧 0303 和新框架 P20 `S_LINE` 都读 `U_BaseType IN ('WW','MRV1')`），再由 MR01 借存货、贷 140803。所以 **PUR3 必须在成本计算之前运行**，此前说它“与成本计算无关”是错的。现有月结顺序里没有这一步。X0510001 不是库存物料，没有 OIVL 记录，委外加工费的发票差异只能通过这张重估单进入成本。

**旧代码的问题【读代码，未在数据上验证】**：

1. PUR2 / PUR3 冲回的是本期全部发票凭证在这些科目上的行，重新入账却只覆盖“基于收货 / 退货”的发票行（内连接）。直接开票（不基于收货，或基于采购订单）和基于发票的贷项（价格调整）的分录被冲掉却没有重记，导致 PUR2 / PUR3 借贷不平或科目余额出错。
2. PUR5 冲回收退货凭证的全部科目，PUR1 / PUR4 只重记库存物料和 X0510001。其他非库存物料走收货时，原分录被冲掉，却没有重记。
3. 发票跨月取消：取消发票基于原发票（BaseType 18），连接收货单时匹配不上，被漏掉；系统生成的取消凭证却照样被 PUR2 冲回，暂估没有恢复。
4. 分次开票：每次按 数量 × 暂估单价 冲回，全部开完后，取整产生的余数永久留在 220202。
5. 退货（ORPD）的暂估金额不看 U_IsPrice，收货却看，同一行收货再退回时两边金额口径不同；退货的“单价”列实际是金额（只影响显示）。
6. PUR4 的预览（IsOJDT='N'）引用了未定义的表变量，会报错；PUR2 / PUR3 没有账期锁定检查。

### 8.5 账期状态控制（用户 2026-10-19，Q36–Q40）

账期状态表 `MTC_CA_PERIOD`（一账期一行，变更记 `MTC_CA_PERIOD_LOG`），视图 `MTC_CA_V_PERIOD` 把 B1 锁定合并进来：

```
未计算 OPEN ──正式计算──▶ 已计算 CALC ──生成凭单──▶ 已生成凭单 POSTED ──B1 锁账期──▶ 已锁定 LOCKED
                  ▲  （可反复重算）        │                         │
                  └──────────────────────┘◀──── 撤销凭单（A 角色）───┘
```

- 检查写在数据库里，绕过执行台也拦得住：`MTC_CA_P_PERIOD_GUARD(FcCode, Action)`，Action = CALC（`P_RUN` 正式计算，在建运行头之前）/ BOOT（`P_BOOTSTRAP`，看起始账期）。POSTED 拒绝；上期（起始账期及以后）未生成凭单、B1 账期状态非 N/Y 只警告，写进 P00 步骤（WARN）。B1 锁定仍由 `P_RUN_BEGIN` 拒绝。
- 正式计算成功 → `MTC_CA_P_PERIOD_SET(…, 'CALC', RunId)`；计算后校验不通过也记（生成凭单时再拦）。
- 下期期初（`P20_OPEN`）：上期 POSTED 时取 `PostRunId`，否则取上期最近一次成功正式运行。
- 执行台：“发起计算”页账期旁显示状态；已生成凭单或 B1 已锁定时正式计算按钮置灰并写原因，模拟不受影响；顶栏运行按钮带账期状态，凭单所用的运行标“凭单所用”。
- 已实现（离线，未编译）：`patch_20261019_period.sql` + 03 / 07 / 09 / 10 / 18、执行台 `periodStatus`。
- **凭单功能**（第 5 期，已实现见 8.6；以下是当时的方案）：
  - 生成：只能用 `CalcRunId` = 最近一次成功正式运行、且 POST 校验无 FAIL；同一账期有 RUNNING 的正式运行时拒绝。按 `R_JDT` 每个凭证代码经 Service Layer `JournalVouchers` 建 OBTF（日记账凭单不能用 SQL 写 B1 表），表头 UDF `U_MTC_CARunId`（日记账分录表头，数字 11 位；OJDT / OBTF 共用，凭单过账后带到 OJDT；由用户在 B1 前台手工添加）记 RunId，本地记凭单号；全部成功后 `PERIOD_SET(…, 'POSTED', RunId)`，部分失败要能续做或整体撤销。
  - 撤销：OBTF 全部未过账（BtfStatus='O'）才允许，经 Service Layer 删除后 `PERIOD_SET(…, 'CALC')`；有已过账的拒绝，提示先在 B1 冲销。

### 8.8 库存重估（用户 2026-11-04；`MTC_CA_P55_REVAL`、执行台“库存重估”页）

起因：应付发票 / 贷项与暂估的差额可能把结存冲成负数或单价明显失真。用户要能快速挑出来，选择性生成重估单，再重新计算。

- **清单**：P50 之后由 P55 写 `MTC_CA_R_REVAL_NEED`，只是清单，不写 B1。ZERO = 结存数量 > 0 且金额 ≤ 0；APDIF = 本期发票 / 贷项差额使加权价偏离剔除差异后单价 ≥ `REVAL_DEV_PCT`（默认 10%，用户确认），已有 MRV1 重估的物料算处理过。
- **建议单价**：有差额时 =（期初金额 + 计价入库金额 − 本期差额 − 已有重估）÷（期初数量 + 计价入库数量）；否则取以前最近一期单价，再取最近采购价，都没有由用户填写。
- **调整金额** =（目标单价 − 当前加权价）×（期初数量 + 计价入库数量），服务端按清单重算。
- **单据**：用本人 B1 账号经 Service Layer 建 `@MTC_OMRV`（表头 U_BaseType = MRV1、日期 = 期末；行 U_CalType = ProCost、U_Quantity = 0、存货科目取 OGAR、对方科目取 `@MTC_MRVTYPE` MRV1 的 510199）。要操作权限；只认本账期最近一次成功的正式运行；账期已生成凭单或已锁定时拒绝；同一运行已生成的物料跳过。
- **为什么用 ProCost**【用户确认 2026-11-04】：InvntCost 不进加权价，本期出库和领料仍按异常单价；ProCost 进加权价，出库和期末都按目标单价。本期没有出库时两者相同。
- **影响**：MR02 借 / 贷存货、贷 / 借 510199，费用池 −金额（沿用，用户确认），分摊给其他产品的成本会变，所以生成后必须重新计算。撤销：在 B1 取消重估单后重新计算。
- **手工重估单**【用户确认 2026-11-04】：B1 里手工建的 `@MTC_OMRV` 与执行台生成的同样生效（MRV1、未取消、日期在本账期）。运行之后才新增的同物料 MRV1 单不在这次运行的快照里，清单的当前加权价没算上它，生成重估单时跳过并提示先重新计算，避免重复调整。单据日期落在已生成凭单的账期、没进该账期结果的，由 PRE-29 报出（只警告）：取消后改到未生成凭单的账期重做，或撤销凭单后重新计算。

### 8.8.1 已取消订单按当时状态看（用户 2026-11-04）

订单在期末之后才取消时，期末当时它还在生产：总账里有它的在产品，期初要承接（如 9 月发料、10 月全部退回、10-27 取消的订单）。`OWOR` 没有取消日期，取 `UpdateDate`，所以取消之后再改过订单，日期会往后偏。规则：期初承接取“未取消，或取消日期晚于承接账期末”的订单；每月计算把本期及以后才取消的订单算在范围内，本期取消的按关单处理，剩余在产品转关单差异。`P20_ORDER`、`P_BOOTSTRAP`、`P_WW_HIST_LOAD`、`order.sql` 同一口径。

**问题**：旧 CO4001 委外订单关单日期 >= 2026-08 才把在产品转关单差异，更早关闭的留在 140801；期初承接只取未关闭订单，所以这些订单业务端为 0、总账仍有余额，构成 140801 期初差额的主要部分（读代码，比例以 `sql/diag_ww_closed_hist.sql` 的结果为准）。

**范围【用户确认 2026-11-04】**：只处理承接前已关闭的历史订单，用来逐步减少财务端差异；新框架起始账期以后关闭的订单在关单当期自动转关单差异（JZ01 / JZ03），不会进这张清单。

**期初【用户确认 2026-11-04】**：承接只取未关闭订单，旧报表 CO4001 的合计含已关闭未转订单，不作为期初。已关闭订单如果进期初，P30 会按关单在首月全部转关单差异，无法分月。所以上线后 140801 期初差额等于待转金额，是预期内的。

**做法**：用户按整张订单选账期转出，不拆金额，负数订单也要转。只处理 140801，不含 140802。

- 清单 `MTC_CA_WW_HIST`：`MTC_CA_P_WW_HIST_LOAD` 从 `MTC_COST_0322_OWOR_ZCP` 载入，取每张订单截至承接账期最后一条记录，范围是 `WW_WORTYPES` 的订单、在产品不为 0、截至承接账期期末不算未关闭（和承接条件互补）。重新载入只替换待转行，已计划的行不动。
- 计划：`MTC_CA_P_WW_HIST_SET` 写 `PlanFc`。主键是订单，所以一张订单只能转一次；已生成凭单或正在计算的账期不能改。
- 计算：P20_EXP 把本期计划写进 `S_EXP`（Src = WWHIST，科目 `WW_HIST_EXP`，成本中心 `WW_HIST_OCR`），按成本中心归池、分摊给当月完工产品。不依赖凭证过账，一次运行得出结果。
- 凭证：P70 生成 JZ05，按用户给的分录两行都记借方：140801 红字（负数）、510109 / P016 正数；510109 由 PP04 转入 500103。`dev_server.py` `jv_body` 把借方负数原样写给 Service Layer。`COST_TRANSCODES` 要含 JZ05（否则过账后 PP04 重复结转），`EXP_JDT_TRANSCODES` 不能含（否则重复进池），由 PRE-30 检查。
- 对账：140801 本期的 JZ05 InRecon = N，不算本期差额，`F_RECON.HistAmt` 单独列示；下期起进期初，期初差额减少。
- 生成凭单：`P_JV_BEGIN` 核对计划与运行快照 S_EXP，计算后改过计划要重新计算。
- 手工转出：`MTC_CA_P_WW_HIST_MARK` 把已手工做分录的订单标记为 Manual = Y，不进计算、不生成 JZ05，只是不能再选。分录已在总账，标记前后 140801 差异不变。
  手工分录不会改 `0322_OWOR_ZCP`，CO4001 也只清关单月份等于当期且 >= 2026-08 的委外订单，所以这些订单的“在产品新”还是原值，清单载入时会列出，要靠标记排除。旧表不改（设计稿总原则），影响只在 2026-09 及以前的旧在产品显示、P65 比对和历史运行 H 的在产品。
- 差异预览：页面取 `F_RECON` 的 WW_MAT，显示现有差异和按当前选择转完后的差异；转完后小于 0（财务低于业务）时红字警告，不阻断。清单合计可能大于实际差异，所以不能默认全转。

**旧框架并行**：旧流程不知道 JZ05。JZ05 的 510109 过账后，旧 0311 只读 YF01 / PP03 / MR02 / MR03 / MR11 / MR12 和 JZ01 / JZ03，不读 JZ05，旧框架的费用里没有这笔。
