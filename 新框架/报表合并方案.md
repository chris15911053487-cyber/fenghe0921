# 新旧框架报表合并：旧框架历史回填成“历史运行”

> **状态：已离线实施，未编译**（用户 2026-11-02 当天要求实施）。四项决定（范围、方式、料工费拆分、并行期）已由用户确认。实施与下面方案不同的地方见末尾“实施说明”。

## Context

新报表 `MTC_CA_RPT_00…20`（`新框架/sql/21_reports.sql`）只读 `MTC_CA_R_*` / `S_*`，经 `MTC_CA_F_RPT_RUN` 取每个账期的运行，**只覆盖 2026-09 起**。2024-12 至 2026-08 的数据只在旧表 `MTC_COST_*` 里，只能用旧报表 `MTC_RPT_CO*` 查看，跨期查询断档。用户要一套报表，从上线起数据连续可查。

已确认的决定（2026-11-02）：
- 范围：从上线 **2024-12** 起全部账期。
- 方式：**一次性回填**，把旧结果转换写进 `MTC_CA_R_*`，作为“历史运行”（RunType `H`）。
- 料工费：旧物料成本只有总额，**按旧订单完工成本比例拆分**（同期初承接 `MTC_CA_BOOT_RATIO`）。
- 并行期：`BOOTSTRAP_FC` 及以前取历史运行，以后取新框架；旧框架 2026-09 以后的结果只进 P65 比对。

## 方案

### 1. 运行与取数规则（改动小，报表过程基本不动）
- `MTC_CA_RUN` 新增 RunType `H`（旧框架回填），Scenario `LEGACY`，每个账期一个；Msg 记来源和回填时间。
  所有现有 `RunType = 'F'` 的判断（P20_OPEN、PRE-23、SRT、P71、执行台运行列表默认值）不会选到 H 运行。
- `MTC_CA_F_RPT_RUN`（`21_reports.sql`）：`COALESCE(PostRunId, CalcRunId)` 为空、且账期 ≤ `BOOTSTRAP_FC` 时，取该账期最近一次成功的 H 运行；`RunSrc` = “旧框架回填”，`PStatusName` 标“历史”。R00 自动显示来源。
- 回填只允许账期 ≤ `BOOTSTRAP_FC`，起始账期以后拒绝。

### 2. 回填过程 `MTC_CA_P_LEGACY_LOAD(FcFrom, FcTo)`（新文件 `新框架/sql/22_legacy_load.sql`）
按账期从早到晚逐期执行（WHILE 循环）。每期先删掉该账期旧的 H 运行，再建新的，可重跑。各表映射：

| 新表 | 来源 | 规则 |
|---|---|---|
| `MTC_CA_BOOT_RATIO`（按账期） | `0321_OWOR_SUM`、`0321_OWOR1` | 把 `09_bootstrap.sql` 里算比例的那段抽成 `MTC_CA_P_LEGACY_RATIO(FcCode)`，承接和回填共用，保证 2026-08 两边拆分一致 |
| `S_ITEM` | 旧 `U_COILV` 该账期层级 + OITM | 只读信息列 |
| `S_LINE` / `R_LINE` | `0302_INVNTDETAIL1`（CostCode 20，一行 = 一条变动） | 单号、日期、交易类型、仓库、科目、订单（59/60 的 BaseEntry）照抄；金额按物料比例拆成四项 |
| `R_ITEM` | `0301_INVNT`（只取 CostCode 20） | **期初 = 上期 H 运行期末四项**（第一期按本期比例拆分），入库、期末按本期比例拆分，出库四项倒挤；四项合计 = 旧值，保证本期期初 = 上期期末 |
| `S_ORDER` / `R_ORDER` | `0321_OWOR`、`0321_OWOR_SUM`、`0322_OWOR_ZCP` | 完工成本四项 = `1Material / 2ManExp / 3LabAmount / 4WWExp`（1Material 再按领用材料比例展开）；在产品取“在产品新”；关单差异取 ZCP |
| `R_ORDER_MAT` | `0321_OWOR1`、`0322_OWOR_ZCP1` | 期初 = 上期 H 运行期末，本期领料、期末在产品照旧表，结转倒挤 |
| `R_ALLOC` / `R_POOL` | `0321_OWOR2`（CostCode 30 / 40） | 旧框架没有费用池明细：一个虚拟池 `LEGACY`，按订单列分摊额，没有工时 |
| `R_JDT` / `R_JDT_SRC` | `0801_TOOJDT`、`0802_OJDTBASEDETAIL` | 凭证底稿原样转换 |

- 期初承接 `P_BOOTSTRAP` 不改口径，只改为调用共用的比例过程。
- 执行台“B1 维护数据”或“运行”页加“回填历史”按钮（管理权限，后台任务，要求输入账套名确认，与正式计算互斥）；`actions.json` 登记。这会新增一个写操作，CLAUDE.md 中写操作清单同步更新。

### 3. 各报表在历史期的覆盖情况（写进报表说明和 `rpt_defs.json` 的 desc）
- **完整**：R01、R02、R03、R04、R05、R07、R10、R16、R19、R20。
- **部分**：
  - R06、R15：只有按订单的分摊额，没有费用池、工时。
  - R12、R13：费率和工时因素合在“其他”里。
  - R09：业务端取 H 运行，总账照常取 JDT1。
- **第一阶段不做**：
  - R08、R14、R18：旧框架没有发出商品结果表。
  - R17：应付暂估直接读 B1，可以以后用 P20_AP + P73 对历史期补算。
  - R11：没有校验结果。
  - 这些报表在历史期返回一行提示“历史期（旧框架）无此数据”。

### 4. 校验 `新框架/sql/22_legacy_verify.sql`（每段一行不通过数，同 `21_reports_verify.sql` 风格）
- L01：H 运行物料期末金额 = 0301 `QM_Amount`（按物料、账期）。
- L02：订单完工成本 = `0321_OWOR_SUM.Amount`。
- L03：在产品 = ZCP“在产品新”。
- L04：四项合计 = 总额（行、物料、订单三层）。
- L05：本期期初 = 上期期末（四项，跨期连续）。
- L06：2026-08 的 H 运行期末 = `MTC_CA_BOOT_ITEM`，与新框架 2026-09 期初衔接。
- 再对 H 运行跑一遍 V01–V14。旧框架已知缺陷（#28 同号订单重复计费、返工单顺序依赖、形态转换 I05 等）造成的不通过，按账期列出，作为“已知差异”记在说明里，**不修改旧数据**。

## 实施说明（2026-11-02，离线写，未编译）

文件：`sql/22_legacy_load.sql`（`MTC_CA_P_LEGACY_LOAD` 入口、`MTC_CA_P_LEGACY_LOAD1` 单期）、`sql/22_legacy_verify.sql`（L01–L08、H01–H14）、`sql/09_bootstrap.sql`（抽出 `MTC_CA_P_LEGACY_RATIO`）、`sql/21_reports.sql`（`MTC_CA_F_RPT_RUN`、`MTC_CA_F_RPT_HISTONLY`）、执行台“期初承接”页“历史回填”（`doLegacy` / `legacyRuns`）、`build_deploy.py`、`99_drop_all.sql`、`rpt_defs.json`。改前备份 `sql/_backup/*_20261102_before_legacy.*`、`tools/console/_backup/*_20261102_before_legacy.*`、`reports/_backup/rpt_defs_20261102_before_legacy.json`。

与方案不同的地方：

1. **`R_ORDER_MAT` 改为期末在产品倒挤、完工转出取旧值**（方案写的是“期末照旧表、结转倒挤”）。原因：勾稽 V02 / V13 要求“期初 + 投入 + 分摊 − 完工 − 关单 = 期末”。两边都取旧值时只能二选一。旧框架的 ZCP 在产品本来就是“累计领料 − 累计完工材料 − 关单差异”倒挤出来的，所以完工转出保留旧值（订单完工成本 = 旧 `0321_OWOR_SUM.Amount`，与 0302 的 I03 一致，L02 / H01 通过），在产品倒挤，再和 ZCP 核对（L03）。完工材料按 `0321_OWOR1_REG`（旧 0402 写的各材料完工结转）的比例分到材料；委外加工费一行 `#SUBFEE`，按旧框架口径当期全部转出；截至期末已关闭的订单，剩余全部转关单差异。
2. **`R_ITEM` 期末取 0301、出库倒挤**；旧框架期末 ≠ 期初 + 本期收发的差额记 `TailAmt`（R03“尾差结转”列，L07 列出物料数），保证 V03 和跨期连续（L05）。
3. **回填时 `MTC_CA_BOOT_RATIO` 不动**：比例过程返回表变量，承接写 `BOOT_RATIO`，回填只在过程内使用，不会改到已承接的数据。
4. **执行台运行列表不显示历史运行**（`runs` 加 `RunType <> 'H'`）：执行台各页按新框架完整数据设计；历史期看“成本报表”。回填状态在“期初承接”页的列表里。
5. 第一阶段不做的报表（R08 / R11 / R14 / R17 / R18）：区间内只有历史运行时返回一行“说明”（`MTC_CA_F_RPT_HISTONLY`）；跨新旧区间照常算，历史那几个月没有数据。R16 发出商品类别在历史期为 0。
6. 核对：L01–L06 回填与旧表一致；L07 / L08 是旧框架自身的不一致（提示）；H01…H14 = V01 / V02 / V03 / V05 / V06 / V13 / V14 对历史运行再跑一遍（H14 含 2026-08 历史运行 → 2026-09 新框架期初）。
