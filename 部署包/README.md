# 一次性部署包

把旧成本模块（表、视图、表函数、过程、配置数据）和新框架 01–16 部署到一个与 FH100 结构相同的 B1 库。整个 `部署包/` 文件夹可以单独复制到别的电脑上使用，里面没有账号密码。

| 文件 | 用途 |
|---|---|
| `全部部署.sql` | 全部语句，按依赖顺序排好。**由 `python3 新框架/tools/build_deploy.py` 生成，不要手改**；改了 `0921-数据库同步/` 或 `新框架/sql/` 之后重新生成 |
| `部署.bat` / `部署_32位.bat` | Windows：双击运行，用本机 HANA ODBC 驱动（只装了 32 位 HANA Client 时用 `_32位`） |
| `deploy.ps1` | Windows 版执行程序（被 bat 调用；必须保存为带 BOM 的 UTF-8） |
| `deploy.py` | Mac / Linux 版执行程序：`pip install hdbcli` 后运行 `python3 deploy.py`，或 `python3 deploy.py --conn 连接.json` |

## 执行时做什么

1. 连接后显示账号、租户、schema，以及库里已有的旧模块过程数和新框架对象数。
2. 检查 B1 自定义表（`@MTC_COST_IOTYPE`、`@U_CIOTRN`、`@MTC_OWOR` 等 20 张）和所需 UDF（`OWHS.U_IsCost`、`IGN1.U_BaseEntry` 等）是否存在；缺了会列出来。这些由 B1 建，部署包不建。
3. 要求完整输入目标账套名（schema，不区分大小写）确认，和目标不一致就取消；确认后逐条执行：
   - 已有的表、索引、序列、旧模块的视图 / 表函数 / 过程**跳过，不覆盖**，所以在已有旧模块的库（包括 FH100 本身）上执行，旧对象不会被改动；
   - 新框架的表已存在时，紧跟的“补齐缺少的列”语句会把表结构里新增的列 `ALTER TABLE ADD` 上去（不改已有列的类型；2026-10-14 起，老库升级不用再单独执行加列补丁）；
   - 配置数据（交易类型、业务类型、凭证代码等 5 张表）只插入目标库没有的代码；
   - 新框架的视图、过程是 `CREATE OR REPLACE`，配置初值是 `UPSERT`，会更新为本包的版本（新框架配置表中手工改过的初值会被改回）；
   - 视图、过程因依赖顺序失败的，最后自动重试，直到没有新的成功。
   - 部署前还会列出新框架要在 B1 前台新建、目标库里还没有的表 / 字段（`-- @b1new`，来自 `新框架/B1对象登记.tsv`），只提示，不影响部署（2026-10-29）。
4. 列出失败语句和无效对象，日志写到 `部署日志_<时间>.txt`（只有语句状态）。

部署完只执行了 `MTC_CA_P_META_SYNC`。期初承接、计算要另外运行，见 `新框架/sql/README.md`“第一次在新库上验证”。

## 不包含的对象

- `_BACKUP_*`、`_TEST`、`_2024xx`、`_2025xx` 等备份 / 测试对象。
- `MTC_COST_ROLLUP_CALC`：源码与表 `MTC_COST_ROLLUP_DETAIL` 的列对不上，FH100 上也编译不了，没有过程调用它。目标库里如果已有这个过程和视图 `MTC_COST_ROLLUP_V`、且处于无效状态，部署最后会删除（“清理”两条语句；有效的不动，2026-10-29）。
- `新框架/sql/20_b1cfg_check.sql`（B1 成本配置校验视图 `MTC_CA_V_B1CFG_ISSUES`、TN 校验过程 `MTC_CA_P_B1CFG_TN`）：2026-10-29 起**在**部署包里，但有条件：B1 里 `@MTC_CA_PARAM`、`@MTC_CA_POOL` / 1 / 2、`OPRC.U_CalType`、`OITB.U_ItemGrpType` 都在才装（语句带 `-- @needs`），缺了跳过并列出缺什么，补齐后重新部署即可。没有这个视图时 P05 不同步 B1 的计算参数。
- B1 的 `SBO_SP_TransactionNotification`：部署包**不会创建、修改或覆盖**它。计算参数 / 费用池的保存校验是 `新框架/sql/20_b1cfg_tn_snippet.sql` 里的一段，只能人工合入（先备份原过程）。合入后 TN 依赖上面两个对象：执行 `99_drop_all.sql`，或在新库上合入了 TN 却没执行 `20_b1cfg_check.sql` 时，B1 里保存计算参数和费用池会报错存不进去；重新执行 `20_b1cfg_check.sql`，或先把 TN 里那一段注释掉。

## 生成时做的修正

- 同步下来的视图定义缺列名清单：`MTC_VIEW_Document` 的列名取自 `0921-补充对象/`；`MTC_DocType` 第 1 列原名未知，暂叫 `TableName`（代码只用 `DocName`、`ObjType`）。同步工具已修，下次同步后这项修正自动不再需要。
- 字符型列的 `DEFAULT O` 补成 `DEFAULT 'O'`。
- 去掉 `"FH100".` 前缀，对象建在执行时选择的 schema。
- 配置数据中“月/日/年”格式的日期转成 `YYYY-MM-DD`。
