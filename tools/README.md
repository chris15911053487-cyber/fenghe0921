# 在网页里直接运行成本校验

`FH100成本核算关系图.html` 双击打开时是**查看模式**：可以看关系图、字段影响、源码，校验 SQL 只能复制出去执行。

在装有 **SAP HANA Client（ODBC）** 的 Windows 电脑上，用下面的方式打开，就能在“数据排查”页直接运行 C01–C20、T01、T02，结果显示在页面里。

## 使用步骤

1. 把整个项目文件夹复制到那台电脑，目录结构保持不变（需要 `FH100成本核算关系图.html`、`checks\`、`tools\`）。
2. 双击 `tools\启动成本核算排查.bat`。
3. 按窗口提示操作：
   - 选择本机已有的 HANA ODBC 数据源，或输入服务器地址和端口（如 `192.168.1.10:30015`）。
   - 输入数据库账号和密码。密码只保存在这次运行的内存里，不会写入任何文件。
   - 可以选择保存连接信息（不含账号密码，存在 `tools\connection.txt`），下次直接回车即可。
   - 选择要使用的 **SCHEMA**：窗口会列出含有成本核算表的 SCHEMA，输入编号或名称，直接回车使用上次的选择（第一次默认 `FH100`）。选择保存在 `tools\schema.txt`。也可以在命令行用 `-Schema 名称` 直接指定。
4. 浏览器会自动打开 `http://127.0.0.1:8765/`。页面顶部会显示当前连接（数据源或服务器、账号、SCHEMA），浏览器标签也会带上 SCHEMA 名。到“数据排查”页：
   - 选账期，点 **按顺序运行 C01–C20**，看第一个“不通过”的是哪一项。
   - 或在单个校验里点 **运行**。T01 需要先填物料编码，T02 需要先填订单号。
5. 用完关掉黑色窗口即可，服务随之停止。

## 从数据库同步脚本

在“源代码”页左上角点 **从数据库同步脚本**：

- 从 `MTC_COST_*`、`MTC_CO_*`、`MTC_PRT_CO*`、`MTC_RPT_CO*` 过程/函数和 `MTC_COST_*`、`U_COILV` 表出发，沿 `SYS.OBJECT_DEPENDENCIES` 自动补齐它们调用的视图、函数、过程和表；
- 过程、函数、视图取系统视图中的原文，自定义表（`MTC*`、`@*`、`U_*`）按字段目录生成表结构，B1 标准表只列名称；
- 另外导出几张配置表的数据：`@MTC_COST_IOTYPE`、`@U_CIOTRN`、`@MTC_MRVTYPE`、`@MTC_SALORDTYPE`、`OTRC`；
- 按关键字 `ProWW`、`MTC_OMRV` 在本 schema 的过程和触发器定义中搜索，把名称不以 MTC_ 开头、但会写成本相关数据的对象也补进来（清单中来源显示为“关键字 …”）；
- 导出 B1 主数据到 `0921-数据库同步\主数据\`：OACT 科目表、OITB 物料组、OGAR 物料组科目确定、OWHS 仓库、OPRC 成本中心、OITM 物料主数据（只取常用字段和全部 U_ 字段）。这些文件只供分析，不会放进网页；
- 结果写入项目的 `0921-数据库同步\` 文件夹（每次同步会整体覆盖这个文件夹），附 `清单.tsv`（每个对象与导出包/对话版本是否相同）、`依赖关系.tsv`、`同步时间.txt`；
- 页面上会标出“有变化”和“新”的对象，打开后可以在“数据库版本 / 原版本 / 差异”之间切换。

同步只查询 `SYS.PROCEDURES`、`SYS.FUNCTIONS`、`SYS.VIEWS`、`SYS.TRIGGERS`、`SYS.TABLES`、`SYS.TABLE_COLUMNS`、`SYS.CONSTRAINTS`、`SYS.OBJECT_DEPENDENCIES` 和上述配置表、主数据表，同样在只读事务中执行。如果某些对象显示“无法读取定义”，通常是账号没有查看其定义的权限。

把同步后的整个项目文件夹交给维护人员，运行 `python tools/page_build/build.py`，生成的网页就会以数据库版本为准，并保留原版本供对比。

## 安全设计

这个程序只做查询，即使用的是有写权限的账号：

- 只执行 `checks\MTC_COST_CHECKS.sql` 里预先写好的查询，网页无法提交任意 SQL；
- 执行前检查语句只能以 `SELECT` / `WITH` 开头，且不含 `INSERT`、`UPDATE`、`DELETE`、`CALL` 等写操作关键字；
- 每次查询都在声明为只读的事务里执行，结束后一律回滚；
- 账期、物料编码、订单号先校验格式，再作为参数传入，不会拼接进 SQL；
- 只监听本机 127.0.0.1，同一网络中的其他电脑访问不到；也拒绝来自其他网站的请求。

建议以后向 IT 申请一个只对 FH100 有 `SELECT` 权限的专用账号，用它来连接。

## 常见问题

| 现象 | 处理 |
|---|---|
| 提示找不到数据源或驱动（IM002 等） | ODBC 驱动的位数要和程序一致。本机只装了 32 位 HANA Client 时，改用 `启动成本核算排查_32位.bat` |
| 窗口一闪就关掉 | 右键 `.bat` → 编辑，确认没有被改动；或在 PowerShell 中运行 `powershell -ExecutionPolicy Bypass -File tools\cost_server.ps1` 查看报错 |
| 被公司安全策略拦截脚本 | 需要 IT 允许运行该脚本（脚本内容可直接用记事本打开审阅） |
| 某个校验运行很久 | C04 会扫描整张 OIVL，数据量大时较慢；单次查询超时为 15 分钟。避开业务高峰运行 |
| 想改端口或 schema | 在 PowerShell 中运行 `... -File tools\cost_server.ps1 -Port 9000 -Schema FH100` |

## 维护

- 校验 SQL 在 `checks\MTC_COST_CHECKS.sql`。程序每次运行都会重新读取这个文件，改完不用重启。网页上显示的 SQL 说明需要重新生成网页才会更新。
- 重新生成网页（需要 Python 3，在任何一台电脑上都可以）：`python tools/page_build/build.py`

## 使用

1. 先用 `部署包/` 把新框架部署到目标账套。
2. Windows 上双击 `tools\启动成本执行台.bat`（只有 32 位 HANA Client 时用 `_32位.bat`）。连接方式与排查服务相同，共用 `tools\connection.txt`。启动时不再在窗口里选账套（2026-10-23）：网页打开后，数据库账号能看到、且部署了新框架的账套有多个时，首页先选**公司（账套）**，选择记在本机浏览器，以后顶栏的下拉框随时切换；只有一个时直接进。窗口里的服务按网页所选公司逐个请求切换账套，最近用的记在 `tools\console_schema.txt`（命令行 `-Schema 名称` 指定默认）。
3. 浏览器打开 `http://127.0.0.1:8766/`。版面（2026-10-14 改）：顶栏左边是运行切换按钮（点开是运行记录，带状态和“刷新”），计算进行中旁边有进度标签（点它看“步骤”），右边是连接信息和“发起计算”；左侧导航分组：本次运行（步骤、计算过程、校验、期初价维护）、存货、订单与费用、财务、比对与说明、操作（发起计算、模拟场景、期初承接）、配置与帮助（B1 维护数据、说明书、AI 助手）；主区上方是所选运行的概况卡片。窄屏时导航收进“菜单”按钮。页面地址带 `#页面`（如 `#orders`），可以收藏或直接打开。

   - **阻断时看当月交易**（2026-11-04）：阻断或只做检查的运行，“收发存明细”页查计算前快照（同类运行只留最近一次，没有计算成本），不输入条件点“查询”= 查全部；校验页 PRE 明细点行看对应物料、单据或订单的交易。

## 安全

- 和排查服务分开：`cost_server.ps1` 保持只读，写操作只在 `cost_console.ps1`。
- 只执行 `tools\console\actions.json` 中登记的语句；参数先按格式校验，再以参数方式传入。查询在只读事务中执行并回滚。
- 写操作：后台的 `MTC_CA_P_RUN`、`MTC_CA_P_PRECHECK`、`MTC_CA_P_BOOTSTRAP`、`MTC_CA_P_LEGACY_LOAD`（同一时间只允许一个；正式计算、承接和历史回填服务端会再核对确认的账套名），同步的 `MTC_CA_P_SCEN_*`（只写模拟场景表）。都只写 `MTC_CA_*` 表。
- AI 助手不连任何外部服务；审计日志 `tools/console/audit/` 只在本机，不要发布或打包。
- 只监听 127.0.0.1，拒绝其他网站的请求（本机模式）。服务器模式见下一节：B1 账号登录、按 OUSR 权限放行、访问日志。

## 维护

- 新增查询或按钮：在 `actions.json` 登记（`kind` 为 `query` 只读查询、`call` 后台长操作、`exec` 同步小写操作（目前只有模拟场景维护）；参数写进 `validators`；`confirm` 为 `always` / `runTypeF` 时要输入账套名确认），再改页面。两个服务每次请求都会重新读取 `actions.json`。
- 页面文件（2026-10-23 拆分）：`console/index.html` 只有页面骨架（顶栏、菜单、抽屉、对话框），样式在 `console/css/`（`themes.css` 是 Online-report 主题的副本，用 `sync_themes.py` 更新；`app.css` 是执行台自己的样式），脚本在 `console/js/`，按 `index.html` 里的顺序加载，共用全局作用域：`core`（接口、查询、字段名和代码字典）→ `table`（通用表格）→ `drawer`（明细抽屉）→ `xlsx`（导出 Excel）→ `shell`（启动、地址栏链接 / 后退、运行列表）→ `pages`（各结果页 `renderTab`、订单明细）→ `flow`（计算过程图）→ `inventory`（收发存、物料明细）→ `trace`（成本追溯）→ `run`（发起计算、进度、顶栏和菜单）→ `report`（运行比较、计算说明）→ `admin`（说明书、B1 维护数据、生成凭单）→ `scen`（模拟场景）→ `ai`（AI 助手）→ `main`（`init()`）。函数之间可以随意互相调用；只有文件加载时立即执行的代码（给按钮绑定处理函数、读本机设置）不能直接用后面文件里的名字，要写成 `() => fn()`。两个服务只提供 `css/*.css` 和 `js/*.js`（文件名限小写字母、数字、下划线），新加文件放进这两个目录并在 `index.html` 里加一行 `<script src>`。
- 表格点行（2026-10-23）：顶栏下拉框“双击开明细 / 单击开明细”，记在本机，默认双击。双击方式下单击只选中（高亮），双击或选中后按 Enter 打开明细；抽屉开着时单击同一张表的别的行直接切换抽屉内容；↑ ↓ 在最后选中的表格里换行（抽屉跟着变）。抽屉里的表格同样规则（双击往下钻取）。Ctrl / ⌘ / Shift 点行仍是多选求和。实现集中在 `js/table.js` 的 `tblOpen` / `tblSel`，各页面的 `bindRows` 不用管。
- 公司（账套）（2026-10-23）：页面每个请求带上所选公司（本机模式在请求头 `X-Schema`，服务器模式取登录时选的公司），服务端按公司各建一个连接池。多个公司时链接里带 `co=账套`，别人打开就是同一个公司。同一时间仍只允许一个计算（跨公司也一样）：另一个公司在算时，页面顶部显示“公司 X 正在计算”，等它结束才能发起。
- 地址栏链接（2026-10-23）：`#页面?run=运行号`，打开物料 / 订单明细时再带 `&item=物料` 或 `&order=单据类型-Entry`（成本追溯页是追溯的起点）。顶栏和抽屉的“🔗 链接”复制当前地址，服务器模式下发给别人，对方登录后直接打开同一个内容；本机模式的地址只能在本机打开。切换页面、运行和打开明细都记入浏览器历史，“后退 / 前进”可用；运行号不在运行记录里时打开最近一次运行。
- `cost_console.ps1` 必须保存为带 BOM 的 UTF-8。
- 取数 SQL（2026-10-19）：一个结果直接从 B1 单据算出来的独立只读语句，放在 `console/srcsql/*.sql`，按 ①②③… 分段写 WITH，每段开头用中文注释写取数范围和规则，参数只有账期（文件里唯一的 `?`），最后一段以 `-- @result` 开头。`actions.json` 用 `sqlFile` 代替 `sql` 登记（两个服务读取时把文件内容填进 `sql`）；比对用同一个文件加 `resultSql`，替换 `-- @result` 之后的输出，与 `MTC_CA_R_*` 结果逐行比较，只列差异。页面上对应页的“取数 SQL”按钮可以查看、复制（代入账期）、执行和比对。注释里不要写英文问号 `?`，单引号要成对（页面代入参数时按 `?` 顺序替换）。改计算过程的口径时同步改对应的取数 SQL，再用“与计算结果比对”核对。目前有：应付暂估 `ap_accr.sql`（P20_AP + P73）、收发存 `inv_line.sql`（P20_LINE 的 OIVL / OMRV 行；库存物料采购类单据的金额改用应付暂估口径，比对时不比）、发出商品 `goods_out.sql`（F_GOODS_OPEN → R_GOODS_OUT 的数量部分，单位成本来自计算）、订单 `order.sql`（P20_ORDER）、委外加工费 `subfee.sql`（P20_SUBFEE）、费用归集 `exp.sql`（P20_EXP + 按成本中心归池；公摊材料、关单差异由计算产生）。按钮登记在 `index.html` 的 `SRCSQL`（页签 → 语句），订单成本和在产品页有订单、委外加工费两个按钮。单价、出库金额、订单成本这些由计算算出的数没有取数 SQL，各文件开头写明了哪些数不在语句里。打包服务器版会带上 `srcsql/`。
- Mac 上使用：双击 `tools/启动成本执行台.command`（在“终端”中打开；需要 Python 3 和 `pip3 install hdbcli`）。有项目根目录的 `mtc_ca_conn.json` 时可直接回车使用，否则逐项输入服务器、账号和密码，浏览器自动打开，在网页首页选公司（账套）。服务是 `tools/console/dev_server.py`，接口与 Windows 版相同。第一次双击如果提示“无法打开”，在 Finder 中右键 → 打开。

## 服务器部署（Windows 服务器，多人使用，2026-10-18）

`tools/console/dev_server.py --server`：一台 Windows 服务器上常驻，其他人用浏览器打开 `http://服务器名:8766/`，用 **B1 账号密码** 登录。

- **登录**：密码交给 B1 Service Layer `/Login` 验证（OUSR 里的密码是加密的，不能读表比对），验证通过后立即 `/Logout`，不占会话；连续失败 5 次暂停 5 分钟；B1 账号被锁定、密码错误都按 B1 的提示显示。空闲 8 小时（`idleMinutes`）后要重新登录；服务重启后所有人重新登录。
- **权限**：OUSR 自定义字段 `U_MTC_CARole`：`R` 查看（全部查询页）、`O` 操作（另可只做检查、模拟计算、维护模拟场景）、`A` 管理（另可正式计算、期初承接、历史回填）；为空不能登录。服务端判断，页面上没有权限的按钮置灰。正式计算和承接仍要输入账套名确认。操作人一律取登录账号（写进 `MTC_CA_P_RUN` 的 UserCode），页面上不能改。
- **访问日志**：`tools/console/logs/access-年月.jsonl`（登录、登录失败、无权限、发起计算、场景维护、计算结束），服务输出在 `logs/server.log`。日志和 `audit/` 一样只留在服务器上，不要发布或打包。
- **生成凭单**（2026-10-19，设计稿 8.6）：只在服务器模式、管理权限下可用。“操作 → 生成凭单”页列出本期最近一次成功正式计算的凭证底稿，勾选凭证代码后输入账套名和**本人 B1 密码**，用你的 B1 账号经 Service Layer 在 B1 建日记账凭单（待过账，一种代码一张）；之后该账期不能再正式计算。要重算：先在 B1“财务 → 日记账凭单”删除这些凭单（已过账的先冲销），再点“撤销凭单”。AR03 / AR04 自动勾选下月初冲销（参数 `JV_REV_TRANSCODES`）。B1 日记账分录表头字段 `MTC_CARunId`（数字 11）可选，有就写运行号。
- **生成 B1 维护单据**（2026-10-29）：只在服务器模式、操作权限及以上。“期初价维护”“工时维护”页的“生成 B1 单据”先按 B1 当前数据预览，确认并输入本人 B1 密码后经 Service Layer 写 UDO `MTC_COST_QCPRICE` / `MTC_COST_TIME`（UDO 名按 OUDO / UDO1 查）：本期已有单据（未取消、未关闭）就追加到最新一张，没有就新建（表头 U_FcCode = 运行账期）；本期已有非 0 值的物料跳过；已有行但为 0 的，有建议价 / 参考工时就改那一行，没有就跳过并列出；新物料加一行，没有参考值的填 0，在 B1 里补。期初单价行另写物料组、组名、关键物料（OITM.U_KeyItem）、层级和备注（同旧 CAL_1001_CHECK）。写完在 B1 核对，再“只做检查”。代码在 `dev_server.py` 的 `b1doc_*`。
- **公司（账套）**（2026-10-23）：`server.json` 的 `schemas` 列出登录页可选的公司（不写时只有 `schema` 一个，`schema` 是默认公司）。登录页选公司，B1 密码按该公司经 Service Layer 验证，权限读该公司 OUSR 的 `U_MTC_CARole`（同一个人在不同公司可以有不同权限），之后这个会话只看这个公司；顶栏下拉框切换公司要重新登录。每个公司都要部署新框架、建好权限字段（启动时逐个检查）。Service Layer 的 CompanyDB 默认就是账套名，不同时在 `sl.companies` 里写 `{"账套": "CompanyDB"}`。
- 同一时间仍只允许一个计算（跨公司也一样）；其他人看到“运行中 · 某某发起”。查询走连接池（`poolSize`，默认 4 个连接），多人同时查询不排队。

- 开机自动启动，以专门的服务账号运行；**不需要有人登录服务器**，远程桌面断开、注销都不影响。
- 程序意外退出会自动拉起：`run_server.bat` 10 秒后重启，计划任务另有 1 分钟后重启。
- 后台没有窗口，启动时不能停下来等人输入：`server.json` 里的 `schema`（账套）和 `hana` 连接（地址、端口、账号、密码或 hdbuserstore 键）必须写全。手工试运行时一路没有提示问话，后台才能启动。
- hdbuserstore 键、用 `--user-scope` 加密的密码都按 Windows 账号保存，要用**服务账号**创建（`runas /user:.\svc_mtcca cmd` 后执行），否则后台启动连不上库。
- 运行情况看 `console\logs\server.log`（启动、退出、报错）和 `console\logs\access-年月.jsonl`（登录和操作）。

### 安装步骤

1. 在开发机上运行 `python3 tools/console/pack_server.py`，把生成的 `部署包/执行台服务器.zip` 拷到服务器解压（如 `D:\MTC执行台\`）。
2. 服务器装 Python 3.8 以上（python.org 安装包，勾选“所有用户”和“加入 PATH”）。**不需要装 hdbcli**：没有 hdbcli 时服务自动用服务器上已装的 HANA Client ODBC 驱动（`console\hana_odbc.py`，只用 Python 自带模块，2026-10-19）。Python 位数要和 HANA Client 一致：64 位 HANA Client 用 64 位 Python（驱动 `HDBODBC`），只有 32 位 HANA Client 时装 32 位 Python（驱动 `HDBODBC32`），或在 `server.json` 的 `hana` 段写 `"driver"` 指定驱动名。装了 hdbcli 时仍优先用 hdbcli，想强制走 ODBC 就在 `hana` 段加 `"via": "odbc"`。也可以把嵌入式 Python 放在 `执行台服务器\python\`，`run_server.bat` 会优先用它。
3. 建一个 Windows 本地账号（如 `svc_mtcca`）专门运行服务，不要用个人账号。数据库账号需要读当前账套、执行 `MTC_CA_*` 过程，并能读 `OUSR`、`CUFD`。HANA 连接写在 `server.json` 的 `hana` 段，默认写法（2026-10-19 服务器实际采用）：`"hana": { "address": "HANA主机IP", "port": 30015, "user": "数据库账号", "password": "密码" }`，port 写租户库自己的 SQL 端口（3xx15 或 3xx41），不写 `databaseName`；或者写系统库端口 3xx13 再加 `"databaseName": "租户库名"`。密码可以加密：在服务器上执行 `python console\dev_server.py --server --set-password`，输入两次密码，`server.json` 里写成 `"password": "dpapi:..."`（Windows DPAPI，只有这台服务器能解开；加 `--user-scope` 则只有执行加密的 Windows 账号能解开，要用服务账号执行；2026-10-19）。第 4 步仍要收紧文件权限。另一种写法是 hdbuserstore 键 `"hana": { "key": "MTCCA" }`：键按 Windows 账号分开保存，必须用运行服务的账号执行 `"C:\Program Files\sap\hdbclient\hdbuserstore.exe" SET MTCCA "HANA主机:30013@租户库" 数据库账号 密码`（如 `runas /user:.\svc_mtcca cmd` 后执行），否则启动时报 `-10104 Invalid value for KEY`。连接报错：-10709 地址或端口不对；10 / 414 账号或密码不对。
4. `console\server.example.json` 复制为 `console\server.json`，改 `schema`（默认公司）、`schemas`（可选的公司，多个公司时）、`sl.url`（Service Layer 地址，如 `https://HANA主机:50000/b1s/v1`）、`sl.company`、`allowNets`（允许访问的网段）。右键 `server.json` → 属性 → 安全，只留管理员和服务账号。
5. 建权限字段（**在 SAP B1 前台手工加，不用 SQL 或脚本**，用户 2026-10-18）：其他用户先退出 B1 客户端 → “工具 → 定制工具 → 用户定义字段 - 管理” → 展开“设置 → 常规 → 用户” → 添加：字段名 `MTC_CARole`（系统自动加前缀成 `U_MTC_CARole`）、描述“成本执行台权限”、类型“字母数字”、长度 1；“设置有效值”勾选，填 `R` 查看、`O` 操作、`A` 管理，不设默认值。然后在“管理 → 设置 → 常规 → 用户”里打开每个用户，在用户定义字段栏（菜单“视图 → 用户定义字段”）选权限，改完下次登录执行台生效。字段名如果要换，同时改 `server.json` 的 `roleField`。
6. 先手工试一次：服务器上双击 `run_server.bat`，看 `console\logs\server.log` 里是否出现“访问地址”，再用另一台电脑的浏览器打开登录。没问题后**关掉这个窗口**（否则端口被占，后台任务起不来），右键 `install_service.bat` → 以管理员身份运行：输入服务账号和密码、允许的网段，脚本注册开机任务（不限时长，异常退出自动重启）并开放防火墙端口，最后问是否立即启动。之后不用再开任何窗口。
7. 要用 HTTPS 时，把内网 CA 签发的证书和私钥（PEM）放在 `console\`，`server.json` 写 `"tls": {"cert": "server.crt", "key": "server.key"}`，重启任务。账号密码要在网络上传输，建议启用。

### 运维

- **重启**：右键 `restart_service.bat` → 以管理员身份运行（2026-10-23）。确认后它会停掉开机任务、结束还在运行的 `run_server.bat` 循环和 Python 进程、等端口释放、再启动任务，等端口开始监听后显示 `server.log` 最后 15 行和结果。重启会断开所有人的登录（重新登录即可）；**有人正在计算时不要重启**，计算会中断（页面顶栏有“运行中”提示）。60 秒内没起来时按提示看日志。
- **更新程序**：开发机上 `python3 tools/console/pack_server.py` 重新打包，按改动的文件决定要不要重启：

  | 改了什么 | 覆盖哪些文件 | 要不要重启 |
  |---|---|---|
  | 页面、白名单 | `console\index.html`、`login.html`、`actions.json`、`console\css\`、`console\js\`、`console\srcsql\` | 不用，每次请求重新读取；用户刷新浏览器即可 |
  | 服务程序 | `console\dev_server.py`、`hana_odbc.py`、`dpapi.py` | 要，运行 `restart_service.bat` |
  | 配置、证书 | `console\server.json`（不要用打包里的覆盖，包里没有它）、证书文件 | 要，运行 `restart_service.bat` |
  | 启动脚本 | `run_server.bat`、`install_service.*`、`restart_service.*` | `run_server.bat` 改了要重启；`install_service.ps1` 改了要重新运行 `install_service.bat` |

  覆盖时不要删 `console\server.json`、`console\logs\`、`console\audit\`。
- **登录一直“正在验证…”**（2026-10-23）：登录页会显示已等的秒数，90 秒没回应就提示。看服务器窗口或 `server.log` 最后几行，每次登录都有三行：“正在经 Service Layer 验证密码…”→“Service Layer 返回（几秒）”→“登录 某某（权限）”。停在第一行：Service Layer 连不上或很慢（某个公司第一次登录 Service Layer 可能要几十秒；超过 60 秒报“连不上 Service Layer”），检查 `sl.url`、防火墙和 Service Layer 服务；停在“正在读权限”：连不上 HANA。双击 `run_server.bat` 运行时已关掉命令行窗口的“快速编辑模式”，在窗口里点一下不会再把服务暂停。
- 看是否在运行：`Get-ScheduledTask -TaskName 'MTC Cost Console'`（State 为 Running），或看 `server.log` 最后几行。
- 卸载：`Unregister-ScheduledTask -TaskName 'MTC Cost Console'`，`Remove-NetFirewallRule -DisplayName 'MTC Cost Console'`。
